# Power BI dashboard

This folder holds the Power BI project for the FP&A case study: one semantic model
(18 tables, 28 relationships, TMDL) and one five-page PBIR report.

> **Status: complete.** All five pages are built, validated with
> `powerbi-report-author validate`, and reviewed from a fresh render. The only
> remaining validation messages are three pre-existing metadata errors
> (`PBIR_THEME_FILE_NAME_MISMATCH`, two `PBIR_JSON_FILE_NO_SCHEMA`) that do not
> affect rendering or data.

## Format: `.pbip`, never `.pbix`

The dashboard is versioned as a **Power BI Project (`.pbip`)**. The semantic model
is stored as TMDL and the report as text, so both are diffable and reviewable in a
pull request.

`.pbix` files are binary blobs: no diff, no review, no meaningful history. They are
excluded from version control.

```
FPA_Case_Study.pbip
FPA_Case_Study.SemanticModel/   # tables, relationships, DAX measures (TMDL)
FPA_Case_Study.Report/          # pages and visuals
```

To save in this format: `File → Save as → Power BI Project (*.pbip)`. If the option
is not visible, enable it under `File → Options and settings → Options → Preview features`.

## Data source: a parameter, not a hardcoded path

Power BI stores absolute file paths when connecting to CSVs, which breaks for
anyone who clones the repository. All connections therefore go through a single
Power Query parameter:

| Parameter | Default value | Purpose |
|---|---|---|
| `pDataFolder` | `..\data\processed` | Folder containing the exported analysis tables |

Every table loads from `pDataFolder`. If the default does not resolve on your
machine, change that one value in `Transform data → Manage parameters`.

Data is never loaded directly from the raw Excel workbooks. The pipeline exports
small, purpose-built tables to `data/processed/` first, so the dashboard always
reflects a reproducible build rather than a manual refresh.

## Pages

Each page answers exactly one question, and every number on it is executed against
the live model before it is written.

| Page | Question it answers | Main visuals |
|---|---|---|
| `01 \| Summary` | How did the business perform over the last five years? | KPI cards, five-year P&L column chart, gross-margin trend line, year matrix |
| `02 \| Profitability` | Which product line created the margin — and which one destroyed it? | Margin % by line, revenue mix, gross-margin contribution |
| `03 \| Variance` | Where did the budget miss, and by how much? | Driver bridge, year matrix, operating-expense variance |
| `04 \| Forecast` | Can the forecast be trusted? How wrong was it, and in which direction? | 2030 scenario band, backtest fold matrix, error by headline line |
| `05 \| Market` | Why is the capacity the constraint, not price? | Market-share trend, unserved demand, unserved units by product |

Hidden report page tooltips are bound to every KPI card and chart.

## Theme and layout

Canvas 1920×1080 on `#F5F7FA`, 12-column grid (139 px columns, 16 px gutter, 32 px
margins). Palette: primary `#1F3864`, secondary `#2E75B6`, neutral `#8C8C8C`, card
`#FFFFFF`. Shared skeleton per page: header textbox, horizontal page navigator,
four KPI cards, two chart rows and a takeaway textbox.

## DAX conventions

- Measures over calculated columns wherever the value is aggregated at query time.
- One measure per business concept, named in business language (`Gross Margin %`,
  not `GM_PCT_Calc`).
- No hardcoded filter values; slicers and parameters drive the context.
- Time intelligence uses an explicit date table, not `AUTOEXISTING` on fact dates.
- Never sum an unscoped fact: `fact_forecast` and `fact_backtest` carry two
  regimes, so every measure filters to one regime (`dim_regime[regime_key] = "A"`).
- The model culture is `es-PE`, so automatic display units render Spanish suffixes
  (`mil`, `mill.`). Charts that need a scale divide in DAX and carry `K` or `M` as
  a literal in the format string, with `labelDisplayUnits: 1D`.
- New measures go into `_Measures.tmdl` only; see the `fpa-model-conventions`
  skill before editing the model.

## Text rules

Every user-facing string is English: page names, titles, subtitles, card labels,
matrix headings, tooltips, takeaways and rendered display units. A Spanish Power
BI Desktop UI is application chrome and is not part of the report. Details in
`dashboard/AGENTS.md`.
